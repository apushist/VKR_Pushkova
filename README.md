# VKR_Pushkova
> Код системы в файле interface.ipynb
### Описание проекта
Разработка системы для помощи начинающим и/или незнакомым с классической нотацией гитаристам, которая сможет предоставить инструкцию по тому, как следует исполнять произведение по нотам с изображения (скана).

**Особенности работы с изображениями нот (Optical Music Recognition):** очень большое количество мелких объектов на изображении. В отличие от типичного OCR (Optical Character Recognition), необходимо работать в двумерном пространстве: для музыкальных знаков имеет критическое значение не только их порядок слева направо, но также и их расположение по вертикальной оси. Работа с контекстом также имеет совсем другие принципы, чем при распознавании текста, так как связь между музыкальными символами подчиняется другим законам.

### Цель и задачи
**Целью данной работы** являлась разработка интеллектуальной системы на основе нейронных сетей, способной распознавать нотные партитуры для гитары по изображениям (скан-копия, фотография) и формировать для каждой ноты указания по выбору оптимальных струны и позиции на грифе, то есть аппликатуру для прочитанных партитур.

**Задачи:**
1. Анализ существующих методов для распознавания нотных партитур по изображениям.
2. Разработка оптимальной архитектуры системы, сочетающей детерминированные алгоритмы с нейронными сетями.
3. Реализация детерминированного алгоритма для определения позиций нотных линий на изображении.
4. Поиск подходящего набора данных и его предобработка для работы с выбранной архитектурой нейронной сети.
5. Обучение модели нейронной сети для распознавания музыкальных символов на изображении.
6. Разработка алгоритма для объединения данных, извлеченных из изображения вышеописанными методами, и формирования списка нот.
7. Разработка подсистемы, преобразующей сформированный список нот в аппликатуру для классической шестиструнной гитары.


### Архитектура системы:
#### 1. Коррекция угла наклона и детекция нотных линий.
#### 2. Определение других музыкальных элементов.
#### 3. Объединение полученных данных для формирования списка нот.
#### 4. Создание рекомендаций по выбору струны и лада.
Алгоритм распознавания музыкальных символов был частично вдохновлен архитектурой [**Audiveris**](https://github.com/audiveris/audiveris).

### Коррекция угла наклона и детекция нотных линий.
Используется вероятностное преобразование Хафа для поиска линий, среди них отбираются те, которые наклонены на угол до 10 градусов.
Изображение поворачивается на медиану углов найденных линий.
<img width="756" height="503" alt="image" src="https://github.com/user-attachments/assets/1b3a23cc-0cee-4235-b688-6578c28bdee6" />

На выпрямленном изображении строится горизонтальная проекция пикселей, и пики на этой проекции считаются координатами нотных линий. При этом шумы могут вызвать ложную детекцию: для борьбы с этим, все обнаруженные линии объединяются в группы по расположению, и те из них, которые не составляют группу из 5 элементов - стан, не учитываются дальнейшим алгоритмом.

### Определение других музыкальных элементов.
Изображение масштабируется и нарезается на фрагменты 640х640 пикселей для согласованности с изображениями датасета, на котором обучалась нейросеть, а также для того, чтобы не потерять мелкие объекты.

Фрагменты пропускаются через нейросеть для обнаружения музыкальных элементов, а затем полученные данные объединяются для возвращения в координаты оригинального изображения.

Используется YOLO26-nano в связи с ограничением ресурсов для обучения. На тестовых данных удалось добиться точности 63,2%.

**Значения метрик на тестовом наборе (3288 изображений, 138254 объекта)**

| Precision | Recall | mAP50 | mAP50-95 |
|-----------|--------|-------|----------|
| 69,8%     | 83,7%  | 74,6% | 63,2%    |


### Объединение полученных данных для формирования списка нот.
Все обнаруженные объекты распределяются по станам, привязываясь к ближайшему по высоте и внутри этого распределения сортируются по горизонтальному порядку. Они дополнительно разделяются по классам на 3 группы: ноты, знаки альтерации и скрипичные ключи. Происходит отдельная детекция знаков при ключе (знаков, действующих на весь стан) и после этого рассчитывается высота каждой ноты (каждой ноте присваивается название, содержащее ноту и октаву), при этом учитываются как знаки при ключе, так и случайные знаки альтерации. Для снижения влияния ошибочных детекций символов на листе, те объекты, которые находятся за пределами возможных местоположений нот, игнорируются.

### Создание рекомендаций по выбору струны и лада.
Когда гитарист первый раз разбирает новое произведение, он принимает решение на каких ладах и струнах будут исполняться отдельные ноты. При этом необходимо учитывать физическую возможность сыграть записанный аккорд и избегать большого количества «прыжков» по грифу. Однако, иногда для обеспечения плавного перехода к высокой ноте, исполнение которой на данной позиции затруднительно или невозможно, необходимо заранее переместить руку в иную позицию. 

В системе для решения вышеописанной задачи используется метод динамического программирования – алгоритм Витерби. Для каждой ноты или аккорда формируется список всех возможных позиций для их проигрывания и с помощью алгоритма выбирается оптимальная последовательность этих позиций.

Ключевые свойства:
- Квадратичный штраф за прыжки > 3 ладов «заставляет» алгоритм заблаговременно
  перейти на другую струну, а не совершать возвратные прыжки.
- Открытые струны (лад 0) не влияют на позицию руки — нулевой штраф.
- Лёгкое предпочтение первой позиции (нижним ладам) при равных затратах.

-	На нижнем изображении построенная на основе полученных данных табулатура. Это распространенная система графической нотации для струнных инструментов, в которой гориз. линии соотв. струнам, а числа на них - № прижатых ладов.
